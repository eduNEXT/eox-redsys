# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decisions in `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the task.
If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals, and code.
Surface conflicts with existing ADRs explicitly, naming the ADR
and explaining why the decision should be reconsidered.
